# Инструкция для агента: реализация «Гараж» в Flutter-приложении OILGID

## Контекст

Бэкенд уже полностью реализован. Твоя задача — реализовать в Flutter-приложении модуль «Гараж»: экраны, модели данных, API-клиент и навигацию. Ничего на бэкенде трогать не нужно.

---

## Авторизация

Все запросы требуют заголовка:
```
Authorization: Bearer <sanctum_token>
```

Токен уже используется в приложении для других запросов — используй тот же механизм.

**Важно:** все эндпоинты гаража защищены энтайтлментом `garage_book`. Это значит, что функционал доступен только пользователям с активной подпиской, включающей этот энтайтлмент. Проверяй наличие `garage_book` в списке энтайтлментов из `/api/subscription/status` перед показом раздела. Если энтайтлмент отсутствует — показывай заглушку с предложением оформить подписку.

---

## Формат ответов API

Все ответы оборачиваются в единый конверт:

```json
{
  "success": true,
  "data": { ... },
  "message": ""
}
```

При ошибке:
```json
{
  "success": false,
  "message": "Текст ошибки"
}
```

## API эндпоинты

Базовый путь: `/api/garage`

### Автомобили

| Метод | URL | Описание |
|-------|-----|----------|
| GET | `/garage/cars` | Список авто пользователя |
| POST | `/garage/cars` | Добавить автомобиль |
| GET | `/garage/cars/{id}` | Получить автомобиль |
| PATCH | `/garage/cars/{id}` | Обновить автомобиль |
| DELETE | `/garage/cars/{id}` | Удалить автомобиль |

**POST/PATCH /garage/cars — тело запроса:**
```json
{
  "modification_id": 12345,
  "nickname": "Моя ласточка",
  "brand": "Toyota",
  "model": "Camry",
  "year": 2020,
  "vin": "XTA210990Y2764680",
  "plate_number": "А001АА777",
  "mileage": 55000
}
```
- При создании `model` — обязательное поле, остальные nullable.
- При обновлении все поля nullable (передавай только изменившиеся).
- `modification_id` — ID модификации из каталога авто (`/api/cars/...`). Если пользователь выбрал авто из каталога — передаётся. Если добавил вручную — не передаётся.

### Сервисная книга

| Метод | URL | Описание |
|-------|-----|----------|
| GET | `/garage/service-records?user_car_id={id}` | Список записей (фильтр по авто) |
| POST | `/garage/service-records` | Создать запись |
| GET | `/garage/service-records/{id}` | Получить запись |
| PATCH | `/garage/service-records/{id}` | Обновить запись |
| DELETE | `/garage/service-records/{id}` | Удалить запись |

**POST /garage/service-records — тело запроса:**
```json
{
  "user_car_id": 1,
  "service_date": "2026-04-15",
  "mileage": 55000,
  "service_type": "Замена масла и фильтров",
  "notes": "Использовано масло Mobil 1 5W-30",
  "total_cost": 4500.00,
  "currency": "RUB",
  "items": [
    { "name": "Моторное масло Mobil 1 5W-30 4л", "quantity": 1, "unit_price": 3200 },
    { "name": "Масляный фильтр Mann", "quantity": 1, "unit_price": 450 }
  ]
}
```
- `service_date`, `service_type`, `user_car_id` — обязательные.
- `items` — массив позиций, необязательный.
- При PATCH — передавай только изменившиеся поля. Если передаёшь `items` — они **полностью заменяют** предыдущий список позиций.

### Медиафайлы к записям

| Метод | URL | Описание |
|-------|-----|----------|
| POST | `/garage/service-records/{id}/media` | Загрузить файл |
| DELETE | `/garage/service-records/{id}/media/{mediaId}` | Удалить файл |

**POST /garage/service-records/{id}/media:**
- Тип запроса: `multipart/form-data`
- Поле: `file`
- Допустимые форматы: jpg, jpeg, png, webp, pdf
- Максимальный размер: 10 МБ

## Экраны для реализации

### 1. Экран «Гараж» (список авто)
- Список карточек автомобилей пользователя
- Каждая карточка: nickname (или марка+модель если nickname нет), год, пробег
- Кнопка «Добавить автомобиль»
- Тап на карточку → экран автомобиля

### 2. Экран «Добавить / редактировать автомобиль»
- Два режима добавления:
  - **Из каталога** — пользователь выбирает марку → модель → поколение → конфигурацию → модификацию через существующий каталог `/api/cars/...`. `modification_id` заполняется автоматически, марка/модель/год подтягиваются из каталога.
  - **Вручную** — пользователь вводит марку, модель, год сам.
- Поля: nickname, VIN, гос. номер, пробег
- Кнопки «Сохранить» / «Удалить» (на экране редактирования)

### 3. Экран автомобиля
- Детали авто (марка, модель, год, VIN, номер, пробег, модификация)
- Кнопка «Редактировать»
- Список записей сервисной книги для этого авто (GET с `?user_car_id=`)
- Кнопка «Добавить запись»
- Тап на запись → экран записи

### 4. Экран «Добавить / редактировать запись сервисной книги»
- Поля: дата, тип обслуживания, пробег, стоимость, валюта, заметки
- Список позиций (items): добавление/удаление строк с названием, количеством, ценой
- Итоговая сумма (можно считать автоматически из позиций или вводить вручную)
- Загрузка фото/PDF (через `multipart/form-data`)
- Просмотр и удаление уже загруженных вложений

### 5. Экран просмотра записи
- Вся информация по записи
- Список позиций
- Галерея вложений (фото — предпросмотр, PDF — иконка с открытием)
- Кнопки «Редактировать» / «Удалить»

## Важные детали

- **Доступность раздела:** перед входом в «Гараж» проверяй наличие `garage_book` в активных энтайтлментах пользователя. Если нет — экран-заглушка с предложением подписки.
- **Удаление авто:** при удалении автомобиля каскадно удаляются все его записи сервисной книги (на бэкенде). Показывай предупреждение перед удалением.
- **Валюта:** поле `currency` — ISO 4217, 3 символа (например, `RUB`, `USD`, `KZT`).
- **Даты:** `service_date` передаётся в формате `YYYY-MM-DD`, в ответах приходит в том же формате.
- **Пробег:** целое число, минимум 0.
- **Ошибка 403** — запись не принадлежит пользователю.
- **Ошибка 403 с `entitlement`** — нет активной подписки с `garage_book`.
